# PoleWatch 앱 기능 명세서

- 대상: 디자이너 핸드오프용
- 근거: `PoleWatch_제안서.pdf` (2026. 9. 18)
- 성격: 복귀 후 사무실에서 보는 **지도 대시보드**. 차량 안에서 쓰는 화면이 아님
- 우선순위 표기: **[필수]** 제안서 명시 / **[권장]** 추가 제안 / **[선택]** 시간이 남을 때

---

## 0. 전제와 제약

- 오프라인 우선
  - 차량의 Jetson은 오프라인으로 기록하고, 복귀 후 Wi-Fi로 동기화한 데이터만 앱에 나타남
  - 실시간 알림, 로그인, 푸시는 범위 밖
- 영상은 저장·전송하지 않음 (개인정보 이슈 회피)
  - 앱에서 볼 수 있는 시각 자료는 **판정 크롭 이미지(전주당 3~5장)와 썸네일 1장**뿐
- 범위 제한
  - 화면은 **지도 1장 + 목록 1장**이 기본 (제안서 명시). 상세·검수 화면은 확장
- 사용 환경
  - 데스크톱 브라우저 기준(1280~1440px). 모바일 대응은 이번 범위 밖

## 1. 용어

- 전주: 배전 전주. 앱의 기본 단위. 전주마다 고유 ID를 가짐
- 위험 유형
  - 까치집 (핵심)
  - 수목 근접/접촉 (확장 클래스, 데이터가 있을 때만)
- 위험 등급 (3단계)
  - 위험 / 주의 / 양호
- 크롭: 전주 상단을 1024px로 잘라낸 판정용 이미지
- 기록: 한 번의 주행에서 한 전주를 판정한 결과 1건
- 처리 상태: 신규 → 확인 → 철거 예정 → 철거 완료

## 2. 화면 구성

- 공통 상단 바
  - 로고
  - 화면 이동: 지도·목록 / 전주 상세·검수
  - 동기화 상태 표시
- 화면 A. 지도·목록 **[필수]**
- 화면 B. 전주 상세·검수 **[필수 + 권장]**
- 화면 C. 기기 상태 **[선택]**

---

## 3. 화면 A. 지도·목록

### 3.1 상단 요약 (KPI) **[권장]**
- 기록 전주 수
- 위험 / 주의 / 양호 개수
- 기준: 현재 선택한 날짜(기본 오늘)

### 3.2 지도 **[필수]**
- 표시 요소
  - 주행 경로 선
  - 전주 마커 (등급별 색상 + 등급 글자)
  - 미점검 도로 구분 **[권장]** (지나가지 않은 구간)
  - 범례 (경로, 미점검, 등급 색)
- 마커 동작
  - 클릭: 선택 상태가 되고 요약 카드를 표시, 목록의 해당 행도 강조
  - 선택 마커는 크기를 키워 구분
- 요약 카드 (선택한 전주)
  - 썸네일 1장
  - 전주 ID, 등급 배지
  - GPS 좌표
  - 위험 유형
  - 기록 시각, 처리 상태
  - 버튼: 상세 보기 / 확인 처리(토글)
- 지도 기술 전제
  - Folium/Leaflet 타일 사용. 디자인의 지도 배경은 대체 가능해야 함

### 3.3 목록 **[필수]**
- 행 구성
  - 등급 마커(색 + 글자)
  - 전주 ID
  - 위험 유형 태그
  - 기록 시각
  - 처리 상태
- 동작
  - 행 클릭: 지도 마커와 연동해 선택
  - 진행 순(기록 시각순) 기본 정렬
- 필터
  - 등급: 전체 / 위험 / 주의 / 양호 **[필수]**
  - 날짜 **[권장]**
  - 위험 유형: 까치집 / 수목 **[권장]**
  - 처리 상태 **[권장]**
- 정렬 **[선택]**
  - 우선순위 점수순 (등급, 재방문 추이, 연속 발견 횟수 기반)

### 3.4 빈 상태·예외
- 해당 날짜에 기록 없음: "기록된 전주가 없습니다" + 동기화 안내
- 필터 결과 없음: 필터 초기화 버튼
- 좌표 없는 기록(GPS 미수신): 지도에 표시하지 않고 목록에만 표시하며 "위치 없음" 표기

## 4. 화면 B. 전주 상세·검수

### 4.1 크롭 뷰어 **[필수]**
- 큰 이미지 1장 + 하단 썸네일 5칸(전주당 3~5장, 실제 개수만큼)
- 썸네일 클릭 시 큰 이미지 교체, 현재 번호 표시(예: 크롭 3 / 5)
- 이미지 위 검출 박스와 라벨(까치집, 전주 등)을 겹쳐 표시
  - 박스 표시 켜기/끄기 **[권장]**
- 확대/축소 **[권장]**

### 4.2 기록 정보 **[필수]**
- GPS 좌표
- 기록 시각
- 위험 유형
- 진행 방향
- 등급과 그 근거(예: 까치집 크기 등급) **[권장]**

### 4.3 판정 검수 **[권장]**
- 버튼: 맞음 / 오탐
- 오탐 선택 시
  - 해당 크롭을 재학습용 폴더에 저장한다는 안내 표시
  - 목록과 지도에서 해당 기록을 오탐으로 표기하고 집계에서 제외
- 선택 취소 가능

### 4.4 처리 상태 **[권장]**
- 4단계: 신규 → 확인 → 철거 예정 → 철거 완료
- 단계 클릭으로 변경. 되돌리기 가능
- 변경 이력(누가/언제)은 이번 범위 밖

### 4.5 이력 비교 **[선택 — 일정이 밀리면 강등]**
- 같은 전주를 다른 날 지나갔을 때의 썸네일을 나란히 표시(이전 방문 vs 오늘)
- 변화 요약(예: 둥지 크기 등급 변화)
- 방문 이력이 없으면 "이전 기록 없음"

### 4.6 내보내기 **[권장]**
- 위험 전주 목록을 CSV로 저장 (전주 ID, 좌표, 등급, 위험 유형, 기록 시각, 처리 상태)
- PDF 보고서 **[선택]**

## 5. 화면 C. 기기 상태 **[선택]**

- 표시 항목
  - 온도, 전력, 프레임 드롭, GPS 수신 상태
- 목적: 벤치마크 실험 결과 확인용. 없어도 앱은 성립

---

## 6. 동기화

- 방식: 복귀 후 Wi-Fi로 SQLite 데이터와 썸네일/크롭 이미지만 전송
- 상단 바에 상태 표시
  - 동기화 완료 / 진행 중 / 실패
  - 마지막 동기화 시각 **[권장]**
- 동기화는 같은 전주 기록이 다시 들어와도 중복되지 않아야 함 (전주 ID 기준)

## 7. 데이터 필드 (화면에 필요한 것)

- 전주
  - 전주 ID, 좌표(위도/경도), 진행 방향
- 기록
  - 기록 시각, 위험 등급, 위험 유형, 처리 상태, 검수 결과(맞음/오탐/미검수)
  - 썸네일 1장, 크롭 이미지 3~5장, 검출 박스 정보
- 주행
  - 경로 좌표열, 날짜

## 8. 디자인 시 유의할 점

- 등급은 **색만으로 구분하지 않음**: 글자나 모양을 함께 사용
- 클릭 대상은 44px 이상
- 위험 등급 색과 브랜드 색이 겹치지 않게 정리 (브랜드가 노란색이면 "주의" 색과의 구분 필요)
- 사진 자리는 실제 크롭 이미지(가로 4:3 안팎)가 들어감. 사람과 번호판이 거의 안 찍히는 구도
- 데이터 양
  - 하루 기록은 수십~수백 건. 목록은 스크롤/페이지 처리 필요

## 9. 범위 밖

- 실시간 알림, 푸시, 이메일
- 로그인·권한 관리
- 영상 재생·업로드
- 모바일 전용 화면
- 차량 안 운전자용 UI
- 전선 이격거리 등 정밀 측정 결과 표시

## 10. 미정 사항 (논의 필요)

- 위험 등급 판정 기준(까치집 크기 등급, 수목 접근 등급의 경계)
- 전주 ID 규칙 (GPS 격자 + 진행 방향 기반 예정)
- 이력 비교를 이번 범위에 넣을지
- 수목 클래스 확보 여부 (없으면 위험 유형은 까치집만)
